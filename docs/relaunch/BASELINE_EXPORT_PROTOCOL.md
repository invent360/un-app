# Authorised deployed baseline procedure

Phase 0 source hashes are in `evidence/source-inventory.json`. They do not describe the deployed PostgreSQL, CMS or media state. Obtain the following only through the deployment owner's approved read-only route, with an agreed snapshot time and a named data custodian. Do not commit row exports, credentials, contact/KYC data, private asset bytes or bearer tokens.

1. Record the source environment, database/server version, schema migration ledger (including SQLx version/checksum/success), snapshot time, exporter identity and access approval. Take a transactionally consistent schema-only PostgreSQL dump and a restricted encrypted row export. Capture the exact command/tool versions in the private manifest.
2. For each relevant operational entity, record table/keyspace name, row count, primary-key count, duplicate upstream `(provider, upstream_id)` count, null/invalid reference count, status distribution and source timestamp range. Include users/sessions, offers/licences, allocations/claims, referrals/agreements, rewards/credits/payments, jobs, CMS versions/translations and media metadata. For financial tables, record currency-specific integer-minor-unit totals and liabilities without merging currencies.
3. Export the CMS slug/locale/version/status/relationship manifest and a media object manifest containing logical ID, version, bytes, SHA-256, storage locator category, references and visibility. Record missing/duplicate objects separately. Preserve all ten locale sources and historical/draft content, not only published English rows.
4. Hash each restricted export and manifest with SHA-256 before transfer. Transfer through an approved encrypted channel into a restricted staging area outside the repository. Give engineering a redacted manifest of counts, hashes and discrepancies; never place the private rows or media payloads in CI artifacts or Git.
5. Reconcile staging against the recorded snapshot and source counts before designing Phase 1 mappings. Quarantine ambiguous IDs, invalid dates, missing credentials, unverified activation, conflicting referrals and unmatched financial amounts. An empty or synthetic fixture remains labelled synthetic and cannot stand in for the deployed baseline.

The data custodian must confirm retention, regional access, export approval and a secure disposal date. This protocol is ready to execute when the owner supplies access; the actual deployed export is pending.
